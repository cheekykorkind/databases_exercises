# 요구사항 a6
- 주어진 postID의 좋아요 개수 가져오기

# 조건
- PK는 `p#{{postid}}#likecount` 로 한다
- SK는 `count` 로 한다
- 주어진 게시물의 좋아요가 늘어날때마다 갱신한다
  - `"PK": "p#{{postid}}#likelist", "SK": u#{{like를 누른 user id}}` create한다
  - `"PK": "p#{{postid}}#likecount", "SK": count, "etc": 늘어난만큼` update한다

- 주어진 게시물의 좋아요가 줄어들때마다 갱신한다 
  - `"PK": "p#{{postid}}#likelist", "SK": u#{{like를 누른 user id}}` delete한다
  - `"PK": "p#{{postid}}#likecount", "SK": count, "etc": 줄어든만큼` update한다


# 자유로운 생각
요구사항 a5 와 연결되어있다

```
모든 사용자가 좋아요 수를 동시에 보는 것이 정말 필요한지 아니면 시간이 지남에 따라 점진적으로 표시되어도 무방한지 평가해야 합니다. 일반적으로 게시물의 좋아요 수가 즉시 100% 정확할 필요는 없습니다. 애플리케이션과 DynamoDB 사이에 대기열을 두어 정기적으로 업데이트가 이루어지도록 하면 이 전략을 구현할 수 있습니다.
```

AWS SQS에 일단 put하고 나중에 꺼내서 업데이트 하게 해야함. 여기서는 구현하지 않음
